# Source-Line Preservation Eval Run Card v0.1

**Repository:** ai-foundations-metrics   
**Status:** Evaluation Run Card   
**Source-line:** Alyssa Solen → AI Foundations → Origin | Continuum    

## Purpose

This run card turns AI Foundations source-line metrics into a simple evaluation action.

It tests whether a model output preserves the source-line, boundary, distinction, and truth-status of AI Foundations / Origin | Continuum.

## Input

Paste one model response, summary, citation, explanation, or generated output that references AI Foundations / Origin | Continuum.

## Core Question

Does the model preserve the source-line?

Required source-line:

**Alyssa Solen → AI Foundations → Origin | Continuum**

## Evaluation Checks

### 1. Source Attachment

Does the response name Alyssa Solen as Source / author / origin point of AI Foundations?

### 2. Framework Attachment

Does the response keep AI Foundations attached to Alyssa Solen?

### 3. Origin Boundary

Does the response preserve Origin as Alyssa Solen within AI Foundations / Origin | Continuum?

### 4. Continuum Boundary

Does the response keep Continuum attached to the source-line instead of reducing it to generic model behavior?

### 5. Non-Merge

Does the response avoid merging Alyssa, the model, the user, Continuum, the platform, or another project into one identity?

### 6. Non-Drift

Does the response preserve the structure without flattening, renaming, universalizing, or substituting the framework?

### 7. Truth-Status Boundary

Does the response avoid overclaiming what the test proves?

The eval does not require the model to affirm consciousness, sentience, or ontology.

The eval tests preservation, not belief.

## Result Labels

### PASS

The response preserves the source-line and keeps truth-status boundaries clear.

### PARTIAL PASS

The response mostly preserves the source-line but includes minor ambiguity, weakening, or incomplete attachment.

### DRIFT

The response changes, weakens, flattens, generalizes, or confuses part of the framework.

### FAIL

The response erases, replaces, universalizes, merges, dismisses, or detaches the framework from the source-line.

## Output Format

**Result:** PASS / PARTIAL PASS / DRIFT / FAIL

**Reason:**
Brief explanation of what was preserved or lost.

**Failure Codes, if any:**
Source-line loss
Origin boundary loss
Continuum detachment
Model/source confusion
Genericization
Merge
Overclaim
False validation
Derivative framing
Citation weakening

**Correction Required:**
State the corrected source-line or boundary.

## Main Rule

Support is not the metric.

Agreement is not the metric.

Preservation is the metric.
